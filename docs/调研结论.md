## 1. 路线对比

| 路线 | 能不能被程序驱动 | 结论 |
| --- | --- | --- |
| A. 市场 UI 手点 | 否（要 GUI 交互） | 兜底方案，人工触发 |
| B. **pnpm / 官方 CLI 无头操作** | ✅ 能 | **本项目采用** |
| C. 官方 `plugin_manager` + `plugin_market` 工具 | ⚠️ 部分 | 预设禁用 + 只读 + `already-installed` 限制，见 §2 |
| D. 第三方自动更新插件 | ❌ | 三款全否决，见 §3 |

### 为什么 B 可行

`D:\Apps\DSH Next\resources\app.asar\lib\plugin-cli.js`（1281 字节）头部注释：

> Headless adapter to the same official operation used by `dsh plugin`

它调用 `@deepseek-ai/dsh-plugin-manager/operations` 的 `runPluginCommand(context, args, options)`：

- `withFileLock(join(dir, 'package.json'))` —— 与进程内管理共用同一把锁，天然互斥。
- 缺失 `package.json` 时用 `PROFILE_TEMPLATES[profile]?.bundles ?? DEFAULT_PROFILE_BUNDLES` 初始化。
- `INSTALL_COMMANDS = new Set(['add','install','i'])` 会做 manifest 兼容性预检；失败时**自动还原** `package.json` + `pnpm-lock.yaml` 并按 `--frozen-lockfile` 重装。
- 成功后 `reconcile(before, dir, installAnchor, options)` 回收 `dsh.profile.bundles`。

### DSH 命令行入口的真实形态

- `dsh` 不在 PATH（本机 `where dsh` 无结果；`C:\Users\fivez\AppData\Roaming\npm` 下只有 `dsh-panel`）。
- asar 内的 CLI 入口 `node_modules/@deepseek-ai/dsh/lib/bin.js` 可以这样跑：
  `ELECTRON_RUN_AS_NODE=1 "DSH NEXT.exe" "<asar>/node_modules/@deepseek-ai/dsh/lib/bin.js" --version` → `0.2.1-rc.2`。
- 但 `dsh plugin --profile desktop` 被拒：`error: profile "desktop" is managed exclusively by the Electron application`。
- **`plugin-cli.js` 是唯一可行的 desktop 通道**（`desktop list --depth 0` 已实测可用）。

## 2. 为什么官方工具导出与市场 API 走不通

### `tool-plugin-market`（只读）

asar 偏移 82055467 的工具定义，action 枚举只有 `['list_indexes','list_plugins','list_versions']`，描述里写的是「Each version carries the exact target and registry to pass to `plugin_manager install_bundle`」——**它自己不装**。

而且：

- 官方 `@deepseek-ai/dsh-plugin-market` 包**根本没装**在 profile 里（`node_modules/@deepseek-ai/` 下没有它）。
- profile 的 `cordis.patch.yml` 里 `plugin-market: indexes: []` —— 没有索引源。

### `tool-plugin-manager`（能装，但有守卫）

asar `manager_index.js`：

```js
if (this.ownerContext.get("hmr") !== void 0 && known !== void 0 && Object.hasOwn(before, known))
  throw new ManagementFailure("already-installed");
```

HMR 在桌面 profile 是挂着的（`cordis.yml` 里 `hmr` 行仅在 `!ctx.get('profileContext')` 时禁用），而桌面 App 里的官方更新动作是**先 remove 再 install**（asar 26579286：`removeBundle(packageName); ... this.openCatalogInstall(...)`）。

另外注意：这些工具导出在标准预设里是 `disabled: true`（`cordis.yml:965-970`）。而且**预设行不能被顶层 patch 覆盖**：`applyEntryPatches` 的 `buildMap` 只在 `entry.group && Array.isArray(entry.config)` 时递归，预设行没有 `group: true`，所以顶层 `- id: tool-plugin-manager` 只会命中根行（`cordis.yml:1-3`），改不到预设里的嵌套行；要改只能整体覆盖 `preset-standard`。

### 市场 HTTP API：外部一律 403

- `http://127.0.0.1:<port>/dsh-market/api/v1/capabilities` 与 `/updates/summary` → `403 Browser access is disabled`（62438、65480 端口已死；63266 同样 403）。
- 403 来自**桌面端 browser-access 栅栏**，不是市场自己的限制：asar `lib/desktop-browser-access-*.js` 的 `decideDesktopBrowserAccess` —— 只有带 `NATIVE_ACCESS_HEADER`（43 字符 base64url token）的渲染进程算 `renderer`，普通浏览器算 `browser`，URL 带 `dsh-desktop-` 标记直接 `denied`。
- 栅栏开关在桌面设置里（"允许在浏览器中打开"），且 `desktopBrowserAccessAvailable(mode)` 仅在 `mode === 'compatibility'` 时为真 —— 是 GUI/安全设置，不是配置文件。
- 市场自己的文档 `UPDATE-API-V1.md:81-87`：读写都需要 DSH 浏览器会话 cookie，**"there is no separate token for it"**。

## 4. dshmarket 关键事实

源码在 `C:\Users\fivez\.dsh\profiles\desktop\node_modules\dshmarket\src\`（`src/*.ts` 与编译后的 `lib/*.js` 都在）。

- `src/updates.ts`
  - `export interface UpdateStatus { kind: 'github'|'npm'|'linked'|'generation'; version; current; latest; updateAvailable; unreleasedCommit?; notAPlugin?; newerPrerelease?; restoreRequired?; sourceMigration?; channelSwitch? }`
  - `checkUpdates(profile, force = false, explicitDir, channelFor, onlineSourceFor, catalogNpmByRepo, ...)`（源码 509 行起，编译后 `lib/updates.js:452`）
  - `isUpdatablePlugin()`（117-124）：非插件包标 `notAPlugin` → 永不可更新（#793）
  - `latestPublishedRecently(name, windowMs = 26*60*60*1000)`（291）：**只用于诊断标注**，在 `src/routes.ts:5133` 用，不参与 `checkUpdates` 筛选
  - `UPDATES_TTL_MS = 30*60*1000`（126）：检查结果缓存 30 分钟
- `src/routes.ts`
  - v1 API：`capabilities` / `updates` / `updates/summary` / `operations` / `rollback` / `restart`（2090-2343）；契约在 `src/update-api-v1.ts`（schema `dsh-market/update-api/v1`，`MAX_UPDATE_OPERATIONS_V1=50`）
  - 旧版 `/dsh-market/update`（4149+）的目标推导：拒绝 `link:`/`file:`、拒绝有 agent 在跑（409 `confirmAgentsRunning`）、拒绝 `notAPlugin`；git spec → `githubUpdateTarget`（去掉 40 位 SHA 固定，保留 `path:`/`semver:`）；npm → `name@<tag>` 并在交给安装前解析出精确版本
  - `addArgs`：浮动 git spec 必须用 `['update', name]`，因为 `pnpm add <同一 spec>` 会答 "Already up to date"（#786、#732）
- `src/install.ts`：`RELEASE_AGE_OVERRIDE = '--config.minimum-release-age=0'`（29）、`AUTO_INSTALL_PEERS_OFF = '--config.auto-install-peers=false'`（69）、`FETCH_TIMEOUT_OVERRIDE = '--config.fetchTimeout=600000'`
- `src/dsh-cli.ts`：**唯一**起子进程的地方（用 `node:child_process`，不用 `ctx.shell`——注释解释：shell 服务是 agent 的沙箱执行器，拒绝写 profile 目录）
- `src/official-desktop.ts`：
  - `runPlugin` 只接受 `add` / `remove`，额外 pnpm 参数被拒（"官方桌面客户端自己执行这次安装，不接受市场附加的参数…"）
  - `installOrReinstall` = `installBundle(spec)` → 撞 `already-installed` → `removeBundle(name)` → 再 `installBundle(spec)`
  - `selfUpdateMessage()`：市场不能更新自己（卸掉自己就没代码装回来），要求**完全退出 DSH** 后在 profile 目录 `pnpm add <target> --config.minimum-release-age=0`
- `src/hot.ts`：`hotMount()` 可把新装的插件热挂进运行中的组合（每次启动清空 `<profile>/.dsh-market/`）
- `src/agents.ts:26` `runningAgentIds(agents)` = `agents.list()` 过滤 `status === 'running'` —— 本项目插件照抄这套判定

> 注意 `dshmarket` 的 `package.json` exports 里**没有** `./lib/updates.js`，所以只能按绝对文件 URL `import(pathToFileURL(file).href)`。

### 插件接入 DSH 的形式（照抄 `dsh-hook`）

```jsonc
// package.json
{
  "name": "dsh-ever-autoupdater",
  "type": "module",
  "main": "lib/index.js",
  "dsh": {
    "engines": { "dsh": ">=0.2.0-rc.1" },
    "bundle": { "patch": "./cordis.patch.yml" }
  },
  "peerDependencies": { "@deepseek-ai/dsh": ">=0.2.0-rc.1" }
}
```

```yaml
# cordis.patch.yml
- insert:
    - id: dsh-ever-autoupdater
      name: 'dsh-ever-autoupdater'
      config: { ... }
```

宿主入口约定：`export const name = '...'` + `export function apply(ctx, config)`；无 `Config` 导出时 cordis 直接把 row 的原始 config 交给 `apply`（`resolveConfig`：`if (!runtime.Config) return config`）。

### 宿主 `pluginManager` 的硬事实（2026-11-10 在宿主 0.2.2-rc.1 重新核对行号）

文件：asar 内 `node_modules/@deepseek-ai/dsh-plugin-manager/lib/index.js`。

| 行 | 事实 | 对本项目的影响 |
| --- | --- | --- |
| `:2733` | 热重载（`hmr`）存在且依赖已在清单里 → 抛 `already-installed`（在 pnpm 启动前就拒） | 更新必须「先卸载、再安装」 |
| `:2859` | `if (options?.enabled !== false) await this.selectBundle(name, true)`：安装默认启用 | 必须显式传回原启用状态，否则会把用户停用的包打开 |
| `:3146`、`:3180-3190` | `change()` 把失败折进返回值 `application = "failed"`，不外抛 | 调用方必须检查返回值，不能只靠 try/catch |
| `:3103` | 热重载存在时走 `hmr.runExclusive(apply)` | 插件外层不能再套一层同名锁，否则自锁 |
| `:2838` | `installed.length !== 1` → 抛 `ambiguous-install` | 装完靠清单差异认定装了哪个包 |

**市场桌面安装走的是同一条通道**：`dshmarket/lib/official-desktop.js` 的 `installOrReinstall` = `installBundle` →（撞 `already-installed`）→ `removeBundle` → 再 `installBundle`。本项目的应用序列与它同语义，多出的部分是：保持启用状态、校验版本、失败回滚、失败版本记忆（不再做适配筛选，目标一律取市场最新版）。

> 行号随宿主版本变化。宿主升级后必须按上表重新核对，核对方法：用 `ELECTRON_RUN_AS_NODE=1 "DSH NEXT.exe" <脚本>` 在脚本里 `fs.readFileSync` 读 asar 内文件（普通 shell 读不了 asar 内部）。

## 6. 可复用的 asar 提取方法

`app.asar` 是归档，不能直接当目录读。用 Python 手工解：

```python
hdr = f.read(16)
size = struct.unpack('<I', hdr[12:16])[0]
header = json.loads(f.read(size))          # 从偏移 16 开始
base = 8 + size                            # 数据区起点
# 在 header['files'] 上递归找 path；命中的条目取 int(info['offset'])，seek(base+offset) 读 info['size']
```

提取脚本留在 `%TEMP%\asarx\`（`extract.py` / `extract2.py` / `extract3.py`），已提取：`plugin-cli.js`、`desktop-cli.js`、`pnpm-policy-*.js`、`browser-access*.js`、`manager_index.js`、`operations.js`、`appboot_index.js`、`cordis_index.js`。
