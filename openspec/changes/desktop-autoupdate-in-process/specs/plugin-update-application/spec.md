# Spec Delta

## Purpose

把检测到的更新安全地应用到 profile：先停用、再卸载、再安装、最后校验，任何一步失败都能恢复到更新前的状态，并保持被更新包原有的启用状态。

## ADDED Requirements

### Requirement: 通过宿主管理服务应用更新
系统 SHALL 通过宿主进程内的插件管理服务执行更新（安装、卸载、启用状态变更），而不是通过命令行子进程；命令行子进程仅在宿主未提供该服务时作为兜底。

#### Scenario: 宿主管理服务可用
- **WHEN** 宿主进程内存在插件管理服务
- **THEN** 所有更新动作经由该服务执行，且 profile 清单、bundle 记录与运行中组合的更新在同一事务内完成

#### Scenario: 宿主管理服务不可用
- **WHEN** 宿主进程内不存在插件管理服务
- **THEN** 系统回退到无头命令行通道执行同一组操作，并标明新代码在重启后生效

### Requirement: 更新的执行序列
系统 SHALL 对每个待更新包按固定顺序执行：记录原状态 → 停用 → 卸载 → 安装 → 校验。卸载必须先于安装，因为宿主在热重载存在时拒绝覆盖已存在的依赖。

#### Scenario: 正常更新
- **WHEN** 一个已安装的插件存在可用更新
- **THEN** 系统依次停用该插件、卸载该插件、安装新版本，并校验安装结果

#### Scenario: 安装前必须先卸载
- **WHEN** 目标包已存在于 profile 的依赖中
- **THEN** 系统先完成卸载再执行安装，不会以覆盖安装的方式直接安装新版本

### Requirement: 保持原有启用状态
系统 SHALL 记录被更新包的原有启用状态，并在更新完成后恢复到该状态；原本被禁用的包不得因更新而被启用。

#### Scenario: 原本被禁用的包
- **WHEN** 待更新的插件在更新前处于禁用状态
- **THEN** 更新完成后该插件仍处于禁用状态

#### Scenario: 原本启用的包
- **WHEN** 待更新的插件在更新前处于启用状态
- **THEN** 更新完成后该插件仍处于启用状态

### Requirement: 更新结果校验
系统 SHALL 在安装后校验实际生效的版本不低于更新前的版本；低于更新前版本的安装结果 SHALL 被判定为失败。

#### Scenario: 版本确实升级
- **WHEN** 安装成功且实际生效版本高于更新前版本
- **THEN** 该项被记录为已成功更新

#### Scenario: 安装后版本未升或倒退
- **WHEN** 安装成功但实际生效版本不高于更新前版本
- **THEN** 该项被判定为失败，并触发回滚

### Requirement: 失败回滚
系统 SHALL 在更新失败时把包恢复到更新前的状态（装回原版本与原启用状态），并把回滚结果记录在报告中。

#### Scenario: 安装失败
- **WHEN** 卸载成功但安装失败
- **THEN** 系统尝试装回更新前的版本与启用状态，并在报告中标记已尝试回滚及其结果

#### Scenario: 卸载失败
- **WHEN** 卸载步骤失败
- **THEN** 系统放弃该包的更新，不继续执行安装，并记录失败原因

### Requirement: 运行中任务的熔断
系统 SHALL 在检测到有正在运行的 agent 时，整轮更新降级为只报告不安装。

#### Scenario: 有 agent 正在运行
- **WHEN** 宿主报告存在状态为运行中的 agent
- **THEN** 本轮不执行任何安装动作，所有待更新项被记录为推迟，附带推迟原因

#### Scenario: 没有 agent 在运行
- **WHEN** 宿主报告没有正在运行的 agent
- **THEN** 更新按正常流程执行

### Requirement: 不可移除包的拒绝
系统 SHALL 尊重宿主对不可移除包的保护：这类包不进入更新流程。

#### Scenario: 包被宿主标记为不可移除
- **WHEN** 待更新项对应的 bundle 不可移除
- **THEN** 该项在应用阶段被跳过并记录原因，系统不做强行卸载
