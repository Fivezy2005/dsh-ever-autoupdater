# Spec Delta

## Purpose

判定当前 profile 中哪些插件存在可用更新，产出一份与市场 UI 一致、可直接用于安装的更新清单，并对不可安全更新的项给出明确的跳过原因。

## ADDED Requirements

### Requirement: 市场一致的更新检测
系统 SHALL 以插件市场自身的更新检测引擎为唯一判定来源，使检测结果与市场 UI 显示的更新列表一致；仅当该引擎不可用时，才回退到内置的 npm registry 检查。

#### Scenario: 市场引擎可用
- **WHEN** profile 中已安装 `dshmarket` 且其更新检测模块可被加载
- **THEN** 系统使用市场引擎返回的更新状态列表，且不额外施加市场之外的过滤规则

#### Scenario: 市场引擎不可用
- **WHEN** 市场更新检测模块不存在、加载失败或未暴露检查入口
- **THEN** 系统回退到内置检查，且内置检查只覆盖 npm registry 源的包

#### Scenario: 单一更新来源的可达性
- **WHEN** registry 无法访问
- **THEN** 该次检测不产生任何更新项（不可达不等于可更新），且不抛出未处理错误

### Requirement: 更新目标的确切版本
系统 SHALL 为每个 npm 源的更新项解析出 registry 上确实存在的**精确版本号**，并在写入安装目标前完成存在性校验；不得把未经验证的版本号直接作为安装目标。

#### Scenario: 版本号在 registry 中存在
- **WHEN** 市场报告某 npm 包存在新版本，且该版本号在 registry 的包信息中存在
- **THEN** 安装目标为该精确版本（`包名@版本号`），不随 registry 的 latest 标签漂移

#### Scenario: 版本号在 registry 中不存在
- **WHEN** 市场报告的版本号在 registry 的包信息中查不到
- **THEN** 该更新项被跳过，并在报告中标明原因，不产生安装动作

### Requirement: 不可更新项的识别与排除
系统 SHALL 排除以下更新项并在报告中记录各自原因：市场自身、插件自身、宿主保护或不可移除的包、非插件类的普通依赖、以及预发布版本。

#### Scenario: 排除市场自身
- **WHEN** 待更新项是市场插件自身
- **THEN** 该项被跳过，原因是市场不允许更新自己

#### Scenario: 排除插件自身
- **WHEN** 待更新项是执行更新的插件自身
- **THEN** 该项被跳过，原因是卸载自己会卸载掉执行更新的代码

#### Scenario: 排除宿主保护包
- **WHEN** 待更新项对应的 bundle 被宿主标记为不可移除
- **THEN** 该项被跳过，原因是宿主不允许移除该包

#### Scenario: 排除普通依赖
- **WHEN** 待更新项是 profile 里的普通依赖而非插件
- **THEN** 该项被跳过，原因是市场不更新非插件依赖

#### Scenario: 排除预发布版本
- **WHEN** 待更新项的目标版本是预发布版本，且未显式允许预发布
- **THEN** 该项被跳过，原因是预发布版本不自动安装

### Requirement: 更新的风险排序与数量上限
系统 SHALL 按版本跳变的风险从低到高排序（补丁版本 → 次版本 → 主版本），并在单次运行中施加数量上限；超出上限的项被推迟到后续运行。

#### Scenario: 排序结果
- **WHEN** 同时存在补丁版本更新和主版本更新
- **THEN** 补丁版本更新排在主版本更新之前

#### Scenario: 超出数量上限
- **WHEN** 可更新项数量超过单次运行的数量上限
- **THEN** 只有排序靠前的项被处理，其余项被推迟并在报告中记录
