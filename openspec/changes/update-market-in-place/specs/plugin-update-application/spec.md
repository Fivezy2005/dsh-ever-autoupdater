# Spec Delta

## MODIFIED Requirements

### Requirement: 更新的执行序列
系统 SHALL 对每个待更新的普通插件按固定顺序执行：记录原状态 → 停用 → 卸载 → 安装 → 校验。卸载必须先于安装，因为宿主在热重载存在时拒绝覆盖已存在的依赖。市场自身是唯一例外，按"市场自身的原地更新"执行，不经过停用与卸载。

#### Scenario: 正常更新
- **WHEN** 一个已安装的普通插件存在可用更新
- **THEN** 系统依次停用该插件、卸载该插件、安装新版本，并校验安装结果

#### Scenario: 安装前必须先卸载
- **WHEN** 目标包已存在于 profile 的依赖中，且不是市场自身
- **THEN** 系统先完成卸载再执行安装，不会以覆盖安装的方式直接安装新版本

#### Scenario: 市场自身不走卸载
- **WHEN** 待更新项是市场自身
- **THEN** 系统不停用、不卸载市场，而是按原地更新方式应用

### Requirement: 不可移除包的拒绝
系统 SHALL 尊重宿主对不可移除包的保护：这类包不进入卸载再安装的更新流程。市场自身虽被宿主标记为不可移除，但因为原地更新不移除它，不适用本条拒绝。

#### Scenario: 包被宿主标记为不可移除
- **WHEN** 待更新项对应的 bundle 不可移除，且不是市场自身
- **THEN** 该项在应用阶段被跳过并记录原因，系统不做强行卸载

#### Scenario: 市场自身不可移除但可原地更新
- **WHEN** 待更新项是市场自身，宿主将其标记为不可移除
- **THEN** 该项不被拒绝，仍按原地更新方式应用

## ADDED Requirements

### Requirement: 市场自身的原地更新
系统 SHALL 在市场自身存在可用更新时，调用宿主进程内提供的包管理器，把新版本的精确版本号直接安装到 profile 目录，覆盖已安装版本。系统 MUST NOT 使用系统自带的包管理器，MUST NOT 绕过发布冷却。

#### Scenario: 宿主提供了包管理器
- **WHEN** 市场存在可用更新、无 agent 在运行，且宿主向进程内提供了包管理器与 profile 目录
- **THEN** 系统用该包管理器安装目标版本的市场，并在报告的已更新项里记录来源版本、目标版本与动作

#### Scenario: 宿主没有提供包管理器
- **WHEN** 宿主未提供包管理器或 profile 目录
- **THEN** 该项被标记为失败，原因说明宿主没有提供包管理器，并给出"完全退出 DSH 后在 profile 目录手动更新"的指引，不改动任何文件

### Requirement: 原地更新的结果校验与重启提示
系统 SHALL 在原地更新后读取磁盘上市场包的实际版本，只有它等于目标版本才算成功；成功的项 MUST 在报告中标记需要重启才能生效。校验不通过时该项视为失败，且系统 MUST NOT 自动重启宿主。

#### Scenario: 磁盘版本等于目标版本
- **WHEN** 原地更新结束，磁盘上市场包的版本等于目标版本
- **THEN** 该项记为已更新并标记需要重启，设置页提示用户重启 DSH 后生效

#### Scenario: 磁盘版本与目标不符
- **WHEN** 原地更新结束，但磁盘上市场包的版本不等于目标版本
- **THEN** 该项记为失败，报告里写明实际读到的版本与期望版本，且该目标版本进入失败版本记忆

### Requirement: 原地更新失败的原因分类
系统 SHALL 把原地更新的失败原因归入可读的类别：文件被占用、发布冷却未到、网络或仓库不可达、其他。每类 MUST 在报告里带上包管理器的原始错误文本，文件被占用与发布冷却两类还 MUST 附带下一步建议。

#### Scenario: 文件被占用
- **WHEN** 包管理器因文件被占用而失败
- **THEN** 报告记录原始错误，并建议完全退出 DSH 后在 profile 目录用宿主自带的包管理器手动更新

#### Scenario: 发布冷却未到
- **WHEN** 包管理器因新版本发布时间太短被拒绝
- **THEN** 报告记录原始错误，并说明稍后下一轮检查会自然重试，该版本不进入失败版本记忆
