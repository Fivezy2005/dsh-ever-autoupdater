## REMOVED Requirements

### Requirement: 优先选择适配当前宿主的版本

**Reason**: 用户要求取消这层筛选 —— 该规则会把更新压在旧版上，长期不升。本机实测：`dsh-better-sidebar` 0.32.1 与 `@linxin666/dsh-ssh` 0.4.18 声明需要 `0.2.2-rc.2`，宿主为 `0.2.2-rc.1`，于是两项一直跳过。

**Migration**: 改为「更新目标为市场报告的最新版」。原先"明确不适配则回落/跳过"的行为不再存在；安装失败由宿主拒绝与既有回滚处理，结果落在报告的 `failed`。

## ADDED Requirements

### Requirement: 更新目标为市场报告的最新版

系统 SHALL 把市场报告的版本直接作为更新目标，不因宿主适配声明而改选更旧的版本、也不因适配声明而跳过该项。npm 源仍 MUST 校验该版本在 registry 上确实存在；git 源 MUST 使用其声明的来源引用。

#### Scenario: npm 最新版声明需要更新的宿主
- **WHEN** 市场报告某 npm 包有新版本，且该版本的清单声明需要比当前宿主更新的版本
- **THEN** 安装目标仍是该最新版的精确版本，不回落旧版，该次运行结束后结果由宿主决定

#### Scenario: git 源目标提交声明需要更新的宿主
- **WHEN** git 源的目标提交清单声明需要比当前宿主更新的版本
- **THEN** 该项仍被列为可更新，并在报告中说明是哪个提交

#### Scenario: 宿主拒绝安装
- **WHEN** 宿主因版本要求拒绝安装或安装后加载失败
- **THEN** 该项进入报告的失败区并带真实错误文本，原本的包被还原，下一次运行不重复尝试同一目标版本

#### Scenario: 最新版在 registry 上不存在
- **WHEN** 市场报告的版本号在 registry 上查不到
- **THEN** 该项被跳过并记录原因，不产生安装动作
