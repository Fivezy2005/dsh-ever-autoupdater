# 取消宿主适配筛选，更新目标一律取最新版

## 为什么

用户明确要求：不要"优先选适配版本"，有新版就装最新版。

现在的行为会在两种情况下压住更新：最新版声明需要更新的宿主（`engines.dsh`），就改选一个更旧的适配版；连适配版都没有，就整项跳过。实际后果是本机两个插件长期停在旧版 —— `dsh-better-sidebar` 0.32.0→0.32.1 与 `@linxin666/dsh-ssh` 0.4.16→0.4.18 都因为要求 `0.2.2-rc.2` 而被跳过（报告理由："needs DSH ^0.2.2-rc.2, this host is 0.2.2-rc.1 — and no newer compatible version exists"）。用户不接受这个折中：宁可装最新版，也不要因为宿主版本差一级而停滞。

## 变更内容

只改本仓库：

- `plugin/dsh-ever-autoupdater/lib/index.js`：删除更新目标前的适配判定（npm 的"不适配则回落适配版"、git 的"目标提交不适配则跳过"），目标版本直接采用市场报告的版本。
- `openspec/specs/plugin-update-detection/spec.md`：移除"优先选择适配当前宿主的版本"，新增"更新目标为市场报告的最新版"。
- `openspec/specs/plugin-update-panel/spec.md`：手动更新条款里不再提"兼容规则"。
- `README.md`、`AGENTS.md`：删掉"适配优先"的表述。
- `test/`：删掉适配筛选的对照用例，补"最新版即使声明不适配也照样安装"的用例。

不碰 `D:\Apps\DSH Next\resources\app.asar`（宿主）、不改 `C:\Users\fivez\.dsh\profiles\desktop` 的任何清单、不改市场代码。

## 非目标

- 不升级 DSH 本体。题述的 `0.2.2-rc.2` 不在本仓库职责内。
- 不更新市场自身（`dshmarket` 仍跳过，另有 `update-market-in-place` 变更处理）。
- 不装第三方 updater。
- 不引入"按宿主版本自动选择旧版"的替代机制 —— 用户要的就是不做这层筛选。

## 依赖的宿主行为与失效点

- 安装通道不变：桌面宿主进程内 `pluginManager`（`installOrReinstall`、`already-installed` 守卫、失败折进返回值）。行号证据见 `docs/调研结论.md`。
- 宿主自行校验仍是唯一防线：若插件在加载期因 `engines.dsh` 不符被宿主拒绝，结果会落在报告的 `failed`（含真实错误文本），安装失败走既有回滚。本变更不新增校验，只是把"提前跳过"改成"装了再看结果"。
- 失效点：宿主若改变对不兼容包的加载策略（例如静默禁用而不报错），报告将显示 `applied` 但插件实际未工作。届时需重新核对宿主行为并更新本文件。

## 影响

- 用户可见变化：设置页「插件更新」不再出现"因不适配而跳过"，被跳过的项变为可更新项；装不上时在失败区显示真实原因。
- 风险：装上的插件可能因宿主版本不足而在加载期报错或不可用。这是用户明确选择的取舍；出问题可在设置页把该插件加入"不更新的插件"，或手动重装回旧版。
